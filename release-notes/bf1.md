# Blockfield/porting-lib bf1

## Кратко

Первый выпуск линии bf этого зеркала: только модуль `porting_lib_loot`. `PortingLibLoot.<clinit>` строил `GLOBAL_LOOT_MODIFIER_SERIALIZERS` через `RegistryBuilder.create()` с регистрацией в корневой карте, где ванила в `BuiltInRegistries.validate` пишет ERROR на пустой реестр. Ни один мод пака не регистрирует сериализаторы и не поставляет GLM-датапаки (проверено сканом jar обеих сторон), а `porting_lib_base` (цепочка Create) жёстко зависит от loot-модуля — удалить модуль нельзя, поэтому патч отвязывает реестр: `new SimpleRegistry(KEY, Lifecycle.stable(), false)` вне корневой карты. Поле не-null, тип и поведение идентичны (реестр и был пустым). Остальные 29 модулей зеркала не меняются.

## Для игроков

Изменений для игроков нет, кроме чистоты серверного лога (одна строка `porting_lib:global_loot_modifier_serializers was empty after loading` меньше; подтверждено минимальным стендом: счётчик таких ERROR упал с 9 до 0 вместе с VB-фиксом). Обновляться нужно только за новым пином (имя файла bf1).

## Технические изменения

- `scripts/PatchPortingLib.java` (новый, ASM): последовательность `<clinit>` заменена на detached-реестр, ровно-1, с `--self-test` и load-тестом (прогон `<clinit>` на заглушках, поле не-null). Защита от ветвлённого `<clinit>` (фреймы небезопасны) — сборка падает fail-closed.
- `scripts/patch.py`: рецепт поверх закреплённого зеркального релиза (`files/mods/*-bf1.jar` из опубликованного `import-2.53.0` через GitHub API приватного зеркала, `GITHUB_TOKEN`, сверка sha512 входа), content-id assertion (выход побайтово равен входу кроме патченного класса), `just build`, `README` + `.gitignore` + `BUILD-SHA256SUMS` (sha256 проверенного кандидата, детерминирован, пересобран дважды).
- `SHA256SUMS`: строка loot исправлена на опубликованные байты bf1 (sha256); остальные 29 строк системно устарели (не совпадают с опубликованными ассетами import-2.53.0) — известное предсуществующее состояние, вне зоны этого выпуска, не трогали.
- Проверено: `just check` (11 тестов, self-test с load-тестом, перезапись реального апстрима, content-id кейсы), `just build` дважды до тех же байтов.

## Обновлённые компоненты

Зеркало остаётся на апстриме Porting Lib 3.1.0-beta.90+1.21.1 (loot; accessors на beta.54): изменён один класс одного модуля (`PortingLibLoot`), остальные jar зеркала не пересобирались и не публикуются.

## Совместимость и необходимые действия

Модуль имеет `side = "both"`: после публикации одинаковый новый URL и SHA должны быть закреплены в клиенте и сервере; выпуск парный, production Deploy — только с подтверждением владельца.

## Известные проблемы

- Открытый bot [major] оставлен сознательно: gate стандартного zlib 1.3.2 — репозиторий сам переисполняется в закреплённый интерпретатор, guard срабатывает только при прямом misuse; та же политика канонических байтов, что в sibling-репозитории.

## Источники и ограничения полноты

- Коммиты import-2.53.0..bf1: оформление рецепта (#1–#11, EOL, раннеры, кэш инструментов), `61f20c6` (detach-патч loot, #12: валидный detached-байткод, sha256-манифест, GITHUB_TOKEN в CI), плюс коммит подготовки релиза bf1.
- Проверено локальным `just check` + `just build` с верификацией checksum кандидата и повторной сборкой до тех же байтов; приёмка минимальным стендом (`was empty after loading` 9 → 0, детали в registry-empty-отчёте). Полнопаковый игровой стенд для bf1 не выполнялся.
